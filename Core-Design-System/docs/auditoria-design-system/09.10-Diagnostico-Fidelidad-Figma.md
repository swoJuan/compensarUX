# Categoría A — Diferencias de origen en Figma

> El código es fiel. La corrección, si se decide, debe hacerse primero en Figma.

## A-01 · Contraste del botón primario (decisión de Figma)

- **Figma:** `use/primary/default` = `#ff6600`, con texto `use/text/on-dark/primary` = `#ffffff`. El gradiente de botón arranca en `#ff6600`.
- **Código:** `.mp-btn--primario` = gradiente `var(--use-primary-default)` → `var(--use-primary-hover)` con texto blanco. **Reproduce exactamente el Figma.**
- **Diferencia:** ninguna respecto a Figma. El problema es que blanco sobre `#ff6600` da ≈ 2.9:1 (< 4.5:1 AA para texto de 16px/bold).
- **Acción recomendada:** escalar a diseño. Si se quiere cumplir AA, ajustar en Figma el color de acción para texto blanco (p. ej. base del gradiente en `#e63f0c`) **o** usar texto oscuro sobre naranja. No corregir solo en CSS: rompería la fidelidad.

## A-02 · Color de enlace (decisión de Figma)

- **Figma:** `use/text/link` = `#ff6600` (verificado directamente en el nodo).
- **Código:** `--use-text-link: var(--base-brand-80)` = `#ff6600`. **Fiel.**
- **Diferencia:** ninguna respecto a Figma. `#ff6600` sobre blanco da ≈ 2.9:1 (< 4.5:1).
- **Acción recomendada:** definir en Figma un token de enlace accesible (`#e63f0c` o `#cc5200`) y propagarlo al código. Complementar con subrayado para no depender solo del color (WCAG 1.4.1).

# Categoría B — Infidelidades reales del código

> Aquí el código se desvía de Figma. Son los fixes que mantienen/restauran la fidelidad.

## B-01 · Letter-spacing de la tipografía UI no coincide con Figma

Es la diferencia más sistemática. Figma define letter-spacing explícito en los estilos UI, y el código usa valores menores o distintos:

| Estilo | Figma (letterSpacing / lineHeight) | Código | Diferencia |
|---|---|---|---|
| `comun/Boton` | **2.2px** / lh 1 | `.mp-btn` → `0.022em` (≈0.35px) / lh 1 | tracking muy por debajo |
| `comun/Label` | **1.2px** / lh 1 | `.mp-input-label` → `0.012em` (≈0.19px) / lh 1 | tracking por debajo |
| `comun/Placeholder` | **1.2px** / lh 1 | `.mp-input-field` → `0.012em` | tracking por debajo |
| `comun/Hint` | **1.2px** / lh 1 | `.mp-input-helper` → `0.012em` | tracking por debajo |

- **Nota de conflicto interno de Figma:** `ia-context.md` registró el letter-spacing del botón como "0.352px aprox" (valor medido sobre la instancia), mientras que el **token tipográfico** `comun/Boton` dice `2.2px`. Hay inconsistencia dentro del propio Figma entre el valor aplicado a la instancia y el token. El código siguió el valor de la instancia (~0.35px), no el token.
- **Acción recomendada:** pedir a diseño que confirme el valor correcto (el token 2.2px parece alto para un botón; conviene validar). Una vez confirmado, alinear el código a ese valor único. Idealmente tokenizar el letter-spacing UI en lugar de literales por componente.

## B-02 · Token `--use-state-info-body` inexistente (rompe theming de alertas/toast info)

- **Figma:** el cuerpo de la alerta/toast info usa `use/state/info/text` = `#2d4a67`. No existe un token "info/body" separado.
- **Código:** `_alerts.scss` y `_toasts.scss` usan `var(--use-state-info-body, #0b3954)` — token **que no está definido** en `_tokens-colors.scss` ni en `_theme.scss`, con un fallback literal `#0b3954` que **no coincide con Figma** (`#2d4a67`) y que **no se sobreescribe en Dark/HC**.
- **Diferencia:** doble — color equivocado en Light (`#0b3954` vs `#2d4a67`) y theming roto en Dark/HC para el cuerpo de info.
- **Acción recomendada:** apuntar `--mp-alert-body` / `--mp-toast-body` de la variante info a `--use-state-info-text` (igual que success/warning/error ya hacen). Elimina el token fantasma y restaura la fidelidad.

## B-03 · Radius del input hardcodeado (fiel en valor, no en método)

- **Figma:** radius del input = 16px (= `border-radius/sm`).
- **Código:** `.mp-input-field` usa `border-radius: rem(16px)` literal, no el token `--radius-sm`/`--border-radius-sm`.
- **Diferencia:** el valor es correcto (fiel visualmente), pero se salta la capa de tokens de radius. Si Figma cambia `border-radius/sm`, el input no se actualizaría solo.
- **Acción recomendada:** consumir `var(--border-radius-sm)` en vez del literal. Mismo criterio para cualquier medida hardcodeada que tenga token equivalente (radius 12px de alerts/toasts/modal = no existe token de 12px; ver B-04).

## B-04 · Radius de 12px en alerts/toast/modal sin token en Figma

- **Figma:** alertas, toast y modal usan radius 12px (documentado en `ia-context.md`, medidas de los tableros).
- **Código:** `.mp-alert`, `.mp-toast`, `.mp-modal .modal-content` usan `border-radius: 12px` literal.
- **Diferencia:** el valor 12px **no existe en la escala de radius de Figma** (`xs 8 · sm 16 · md 24 · lg 32`). Es un valor fuera del sistema de tokens, tanto en Figma (lo aplica a mano) como en código (literal).
- **Acción recomendada:** registrar como **pendiente de validar con diseño**: o se añade `border-radius/12` a la escala de Figma (y token en core), o estos componentes deben migrar a `border-radius/sm` (16) para entrar en el sistema. No inventar el token sin confirmación.

## B-05 · Grosor de foco inconsistente (2px vs 3px) dentro del propio código

- **Figma:** el sistema define un indicador de foco único (ring de 3px en los componentes).
- **Código:** `_accessibility.scss` global usa `outline: 2px`; los componentes `mp-*` usan `var(--color-focus-ring-width)` = 3px.
- **Diferencia:** inconsistencia interna del código; el foco cambia de grosor según el elemento, cuando Figma lo trata como uno solo.
- **Acción recomendada:** unificar el reset global y el mixin `focus-ring` a `var(--color-focus-ring-width)` (3px).

# Categoría C — Código sin equivalente en Figma

## C-01 · API legacy (`.btn`, `.input`, `.check-wrap`, `.toggle`) no existe en Figma

- **Figma:** solo define la API `mp-*` (`.mp-btn`, `.mp-input-field`, `.mp-choice`, `.mp-switch`).
- **Código:** conviven activas en `core.css` la API `mp-*` y una API legacy que **no tiene tablero ni tokens en Figma** y que diverge del diseño:
  - `.btn` legacy → radius `$radius-xs` (8px) vs Figma 24px.
  - `.input` legacy → radius `$radius-xs` (8px) vs Figma 16px; placeholder con `--color-text-disabled` (#a4a4a4) vs Figma `use/text/tertiary` (#666).
  - `.check-wrap` / `.toggle` legacy → control nativo con `accent-color` 18px / toggle 44×24, vs Figma `mp-choice` (control 24, hit 44) / `mp-switch` (52×40, knob 28).
- **Diferencia:** la capa legacy es, por definición, infiel al Figma (no deriva de él).
- **Acción recomendada:** marcar legacy como *deprecated* con fecha de retiro (p. ej. v3.0.0), publicar tabla de migración a `mp-*`, y mientras conviva, alinear al menos radius/foco/placeholder a los valores de Figma.

# Quick wins que restauran fidelidad sin tocar diseño

1. **B-02** — Apuntar el body de info a `--use-state-info-text` en alerts y toasts. Elimina el token fantasma y corrige el color a `#2d4a67` (Figma).
2. **B-05** — Unificar grosor de foco a `--color-focus-ring-width` (3px).
3. **B-03** — Input usa `var(--border-radius-sm)` en vez de `16px` literal.

A-01 y A-02 son igual de importantes pero requieren decisión de diseño sobre el Figma, por lo que no entran como quick win silencioso.
